# 재현 안내와 확인 사항

## 공개본 정리 내용

원본 두 노트북의 코드 셀을 보존하되 출력과 실행 번호, 위젯·Colab 등 실행 메타데이터를 제거했습니다. 하드코딩된 Hugging Face 토큰은 환경변수 기반 인증으로 바꿨으며 PubMed 수집 이메일은 `NCBI_EMAIL`에서 읽습니다. 사용자별 Windows/Colab 경로를 저장소 상대경로로 바꿨습니다. 계산 로직과 원고 수치를 새로 검증하거나 다시 실험한 버전은 아닙니다.

## 실행 경로

1. `data/BioASQ-trainingDataset4b.json`과 루트의 `pubmed_title_abstract.csv`를 준비합니다.
2. 평가 노트북의 데이터 전처리 셀로 질문 유형별 CSV를 생성합니다. 수집 셀은 인터넷에서 PubMed 데이터를 다시 가져오므로 기존 CSV가 있다면 건너뜁니다.
3. 임베딩 노트북은 S-BERT, 일반 Transformer, LLaMA 실험 분기가 함께 있습니다. 필요한 분기만 실행하고, `Document`, `RecursiveCharacterTextSplitter`, `Embeddings` import 셀을 먼저 실행합니다.
4. `MODEL_NAME`, `pooling_mode_*`, `COLLECTION_NAME`, `PERSIST_DIR`를 서로 일치시켜 Chroma 컬렉션을 생성합니다. 기본 코드에서 풀링 설정과 컬렉션 접미사가 항상 일치한다고 가정하지 마세요.
5. 평가 노트북의 대형 평가 셀에서 `CHROMA_DIR`, `collection_list`, 입력 CSV 경로를 지정합니다. 기본값은 `500-100/embeddinggemma/chroma_db`, `gemma_C`, `gemma_X`, `gemma_M`입니다.
6. `k_list=[5,10,20]`, `LLM_MODEL="gemma3:4b"` 등 설정을 확인하고 평가를 실행합니다. 출력은 `500-100/result`, `500-100/result_summary`에 저장됩니다.
7. 후반 집계 셀로 질문 유형별 생성 성능을 비교합니다.

`C`, `M`, `X`는 각각 CLS, Mean, Max를 뜻합니다. 원본 코드에는 `CM`, `CX`, `XM`과 논문 범위 밖의 모델도 있습니다. 원고 요약의 네 모델·세 풀링 결과와 혼합하지 마세요.

## 환경

Python, Jupyter, PyTorch, sentence-transformers, transformers, pandas, numpy, scikit-learn, ChromaDB, LangChain 관련 패키지, PyYAML, tqdm, Biopython 등을 사용합니다. 선택 분기에 따라 추가 패키지가 필요하며 설치 셀에 원래 사용한 패키지가 남아 있습니다. 당시 버전, GPU 정보, 완전한 실행 순서가 고정된 환경 파일은 제공되지 않아 임의의 버전 고정을 추가하지 않았습니다.

노트북에는 Colab용 `%xterm` 등 로컬 Jupyter에서 사용할 수 없는 셀도 남아 있습니다. 해당 셀은 생략하고 Ollama를 별도 실행하세요. 모델 다운로드 및 전체 평가에는 시간과 연산 자원이 필요합니다.

## 원고·코드 대조에서 확인할 항목

- **표 4 수치:** factoid 검색 점수가 표에서는 0.6304, 본문에서는 0.6390입니다. 원시 결과에서 최종값을 확인해야 합니다.
- **검색 점수 정의:** 표 4는 `score`라는 이름만 사용합니다. Recall@k인지 nDCG@k인지 또는 합성 점수인지 명시가 필요합니다.
- **데이터 버전:** 원고는 전처리 전 1,307개, 후 1,022개 질문을 보고합니다. 제공된 데이터 README에는 1,307개와 추가 497개 질문이 언급되어 있어 실제 JSON의 개수·버전과 필터링 조건을 대조해야 합니다.
- **Factoid 답변 형식:** 프롬프트는 단일 문자열을 요구하지만 MRR은 후보 순위를 다루는 지표입니다. 후보가 하나라면 역순위 값은 일치 여부에 따라 0 또는 1로 제한됩니다. 원고의 평가 해석과 실제 후보 처리 방식의 일치 여부를 확인해야 합니다.
- **생성 점수 비교:** MRR, F1, Macro-F1의 수치 크기만으로 질문 유형 간 난이도나 성능 우열을 단정하면 안 됩니다.
- **검색 단위:** 검색되는 것은 청크이며 정답 관련성은 PMID 문헌을 기준으로 합니다. 중복 PMID의 처리 방식과 k의 의미를 결과 보고에 명시해야 합니다.

## 이번 공개본의 검증 범위

노트북 JSON 구조, 출력·실행 번호 제거, 알려진 토큰 패턴 제거, 개인 절대경로 제거와 문서 링크를 확인했습니다. 모델 다운로드, 임베딩 재구축 및 전체 질문에 대한 생성 평가는 실행하지 않았습니다. README의 결과는 원고 전사값입니다.
